```
  JMMyModule.c    ← module + RPC dispatch

```

### RPC ranges (from `.claude/docs/rpc_system.md`)
Free ranges above 10800. Plan: **10900** for MapEditor, **10920** for AntiCheat.
Player module extension stays inside `JMPlayerModuleRPC` (10320–10400).

### Standard action shape (player module pattern, applies to new features)
```
public client entry → Exec_* server apply → RPC_* server-side handler
```
Mandatory gates on every action: `IsMissionHost()` short-circuit; `RPC_MAX_GUIDS` cap;
`GetPermissionsManager().HasPermission(...)`; `GetCommunityOnlineToolsBase().Log(...)`;
`SendWebhookColored(...)`.

### Logging — confirmed
`GetCommunityOnlineToolsBase().Log(...)` — 3 overloads (server-only, with `JMPlayerInstance`,
with `PlayerIdentity`). Writes `[COT]` lines to `g_Game.AdminLog` plus per-session file under
`JMConstants.DIR_LOGS` (`cot-YYYY-MM-DD-hh-mm-ss.log`). No `COTLog()` utility.

### Webhooks — confirmed
- `JMModuleBase.SendWebhook(type, message)`
- `JMModuleBase.SendWebhookColored(type, message, color)` / `(type, instance, message, color)`
- Calls `m_Webhook.Post(GetModuleName() + type, msg)` with embed field = `GetWebhookTitle() : message`.
- Per-module opt-in via `GetWebhookTitle()` + `GetWebhookTypes(out array<string>)`.
- Colour constants in `JMConstants.WEBHOOK_COLOR_*` (success / warning / danger / critical).

### Tooltips — confirmed
- `UIActionTooltip` singleton (`s_InstanceRef`), hover delay 1.0s, edge-flip,
  auto-hide on ancestor hidden.
- Per-form: `CreateTooltip(layoutRoot)`.
- Per-widget: `SetTooltip(text, icon, swatchColor, textColor)`. Runtime only, no layout attribute.

### RPC rate limiting — confirmed
`JMModuleBase.IsRateLimited(sender)` map with `JMConstants.RPC_RATE_LIMIT_S`. High-frequency
RPCs (map-editor drag updates, anti-cheat position sync) must consult this before forwarding.
Bulk GUID-array RPCs already dodge per-message limits via `RPC_MAX_GUIDS`.

### Permissions
`GetPermissionsManager().RegisterPermission( "Admin.MyModule.Action" )` in the module ctor.
`UpdatePermission( "permission.string" )` on widgets inside `OnClientPermissionsUpdated()`.

## 5. Anti-cheat — what to detect

Mission text says "detect potential cheaters to prevent exploits". DayZ-relevant signals:

| Signal | How |
|---|---|
| Teleport (impossible positional deltas) | Server-side `OnUpdate` polling position every N seconds, compare with prior position × `dt` against sane max speed (~12 m/s sprinting). |
| Godmode-via-flag | `player.COTHasGodMode()` direct read; flag if true without admin permission. |
| No-clip / fly | Raycast under feet every N seconds; if missing ground → flag. |
| Speed hack | Same position-delta check as teleport. |
| Damage anomaly | Server tracks `SetHealth` deltas per tick; flag if `> sane_max_per_tick` while alive. |
| Out-of-bounds coords | Hard map bounds; flag positions > world radius. |
| Vehicle speed | Same speed check for `HumanCommandVehicle`. |
| Inventory cheats | Server-side mass-spawn detection: count items added per second per player; flag > threshold. |
| Mod-loading / known cheat signatures | Scan `PlayerBase.GetModifiers()` / `GetSymptomManager()` for unexpected active modifiers. |
| Damage-dealt multiplier | Players flagged as dealing > Nx expected damage per hit (admin whitelist excluded). |

Implementation approach:
- New `JMAntiCheatModule` polling loop on server, runs at ~0.5 Hz.
- Maintains `map<string, ref JMAntiCheatState>` per player.
- Per-player score; threshold → broadcast webhook + log + optional auto-action
  (kick / message). Admin configurable thresholds via `JMAntiCheatConfig` JSON.
- Read-only admin UI showing top-flagged players, recent events, ability to clear
  flags or take per-flag actions (teleport-to, spectate, kick, ban).
- **Detection is server-only**, no client RPC spam. Webhook fires only on threshold breach.

## 6. RPC anti-spam — concrete rules to enforce

Pulled from `LootAnalysis_Audit.md` + observed patterns:

- **Search inputs**: debounce 300 ms; never iterate all tracked entities on every keystroke.
- **Per-frame updates**: throttle to 1 Hz; batch; never ship raw per-entity data on every tick.
- **Bulk toggles** (godmode for 50 players): one RPC carrying the GUID array, not 50 RPCs.
  All player RPCs already use `RPC_MAX_GUIDS` cap.
- **Map editor multi-select transforms**: one RPC per mutation, but UI selection RPC is
  debounced to ~5 Hz on the receiving side (drop intermediate positions while dragging).
- **Anti-cheat**: server-only, no client traffic.
- **Player disease add/remove**: existing `Exec_*` pattern handles bulk via the GUID array
  → single server apply → per-player log + webhook via `ProcessToggle`.
